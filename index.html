Why Agentforce, and why now

Agentic automation is a natural extension of that governance work, not a departure from it. An AI agent that can write to Salesforce is, from an architecture standpoint, just another caller — and every caller needs the same guardrails: don't duplicate a side effect on retry, don't let bad input reach the database, don't let a large or unusual action execute unsupervised, and don't leave the org in a half-written state if something fails partway through. I've built that pattern for human-facing integrations for years; I'm now building it explicitly for agent-facing ones.

This is an early-career pivot into AI-driven automation grounded in a decade of Salesforce architecture — not a claim of deep AI/ML research experience.

03 · Public Demo — Agentic Entitlement Grant

A generic, from-scratch rebuild of the governance pattern above

Client work isn't public, so I rebuilt the core governance pattern behind the my.kuka.com entitlement system as a standalone, generic SFDX package — no client code, no client data, just the pattern: how to let an agent request a write, and how to make sure that write is safe.

The point isn't the AI call, which is a single @InvocableMethod. The point is everything downstream of it:

  • Idempotency — a retried request can't double-grant.
  • Validation — nothing touches the database before quantity, SKU, and partner status are checked.
  • Approval gate — a large or unusual grant gets routed for human review instead of executing unsupervised.
  • Savepoint / rollback — a failure partway through can't leave the org in an inconsistent state.

It ships with a 6-test Apex test class covering grant, duplicate, reject, and approval-routing paths.

07 · KUKA — Predictive Maintenance & Agent Platform

Talking-point breakdown of the KUKA AI initiative — predictive maintenance pipeline, agent/MCP tooling, and platform delivery — for walking through the work live.

Opening line: "I built the ingest-to-prediction pipeline on GCP, then made the agent layer that acts on it governed — every prediction is a proposal, every write needs a human approval, every tool call is scoped and audited."

AI Predictive Maintenance Platform

Goal: cut unplanned downtime, shorten service response.

  • Ingest & store — controller telemetry (torque, current, vibration, position error, temperature) streamed into BigQuery as the single analytical store; built for HA, IAM-scoped access, cost-efficient compute.
  • Signal → insight — Vertex AI / Gemini retrieval (grounding + RAG) over the high-frequency signal to strip noise and surface pre-failure patterns, feeding ML models that forecast component-level degradation ahead of the fault.
  • Human-in-the-loop — pipeline connects to enterprise systems of record through an Apigee X-fronted MCP gateway; a prediction raises a risk alert, never a silent action. Approval is a hard gate before any write.
  • Automation after approval — service case, spare-parts order, field-tech dispatch all fire automatically once approved, removing the slowest part of the old manual cycle.

Agent Architecture & Tooling

Goal: make AI reusable across the business instead of per-project.

  • MCP tool surfaces specified as typed contracts before implementation — explicit input/output schemas, scoped permissions, failure semantics, idempotent writes.
  • Built & operate the Apigee X agent/MCP gateway — the governed control point for agent-to-tool and Agent2Agent (A2A) traffic: authN/authZ, tool registration & discovery, rate limiting, policy enforcement, full observability.
  • Defined agent identity and least-privilege access patterns — auditable credentials, scoped tool access, controlled data exposure, defenses against prompt-injection and unauthorized tool invocation.
  • Extended the enterprise data model for grounding/contextual retrieval on Vertex AI / Gemini — agents query structured context instead of inferring it.
  • Designed AI-ready intake & routing workflows with agent action orchestration layered over existing enterprise processes.

Platform Engineering & Delivery

Goal: keep a large install base stable while shipping fast.

  • Owned integration frameworks across SAP, IQWorks, Visual Components, and IQOT — REST APIs, Named Credentials, JWT auth.
  • Architected secure, highly available services on Google Cloud — IAM, networking, compute sizing, failure-mode analysis, blast-radius containment.
  • Ran CI/CD end to end — validation, deployment governance, environment strategy, controlled release, rollback prep, deployment troubleshooting.
  • Supported 100,000+ external and 5,000+ internal users; led architecture & code reviews, mentored developers, technical point of contact across engineering, product, ops.
